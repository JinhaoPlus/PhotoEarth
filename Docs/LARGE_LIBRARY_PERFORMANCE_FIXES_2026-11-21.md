# Photo Earth 万级图库性能修复 · 2026-11-21

验收沿用[前次评估](LARGE_LIBRARY_PERFORMANCE_AUDIT_2026-11-20.md)中的五个用户动作。下文的规模测试使用合成索引，时间为本机 tvOS 27.2 模拟器 Debug 数据。

## 重开图库

原生导航首次在图库可浏览时挂载，之后保留货架和焦点。启动核对随包城市目录清单、匹配策略和 Photos 授权范围。已有可用索引时省去 28,096 条城市的解析和建表，需要重新匹配时再加载目录。有可信基线、范围一致且 Photos 持久更改记录为空时，SQLite 只提交新的同步状态。旧 token、权限或范围变化、中断的暂存、定期全量核对仍走原来的验证流程。

| 操作 | 规模 | 同库原路径中位数 | 新路径中位数 |
| --- | ---: | ---: | ---: |
| 冷资源对象核对目录版本 | 28,096 个城市 | 622.90 ms | 0.59 ms |
| 零变化的 SQLite 暂存及提交 | 1 万项 | 66.36 ms | 12.66 ms |
| 零变化的 SQLite 暂存及提交 | 5 万项 | 206.64 ms | 11.88 ms |

各取三次。目录计时限于版本判断，空增量计时限于数据库步骤，界面启动和 Photos 权限范围枚举另计。[原始数据](../.local-test-data/performance-fixes-20261121/startup-metrics.txt)

## 照片墙和城市封面

- 集合墙、地球当前画面墙和地图回看共用行布局自带的照片位置索引。冻结范围时建立到访 ID 索引，卡片和详情只取自己的地名。切换详情不触发隐藏墙滚动，退回时一次定位到最后观看的照片。关闭地球上的墙会释放这次浏览的元数据和投影。
- 地图回看的卡片也将当前已解码预览直接交给详情，进入后台、切换资产和退出时释放。墙仍按实际读过的页保留位置和日期，以支持反向浏览。
- 应用内的已选静态封面先请求相同照片、当前编辑版本、完整构图的卡片尺寸图。本地够清晰就结束；本地不足可先显示，调度器等卡片可见后请求 iCloud 尺寸图，仍不足时才读取大图数据。四个本机名额可以并发读取封面，可能升级到全尺寸的网络封面同一时刻最多一个。缓存复用时排除已经按另一构图裁切的图。系统主屏海报延续独立的导出路径。

### 深页实测

在独立工程副本中预装已浏览的记录，复用产品照片墙、详情、原生焦点与遥控器输入。两组都向前翻三张、反向一张再退出，XCTest 分别确认第 502 和 5,002 张卡片取得焦点。首次探针曾在第 502 张退回第一行。修复将行注册为原生滚动目标，并在恢复期间仅允许目标照片取得卡片焦点。

| 已浏览位置 | 应用收到方向输入到第一张预览回调，4 次中位数 | 退回墙到目标获得焦点 | 事件处采样的进程物理内存范围 |
| --- | ---: | ---: | ---: |
| 第 500 张 | 8.7 ms | 62.7 ms | 167–178 MiB |
| 第 5,000 张 | 6.8 ms | 65.0 ms | 157–167 MiB |

两组独立启动，各跑一次，使用三种本地公开图的重复资源。这里只测翻页路径到图片回调和焦点状态；屏幕实际呈现延迟、浏览数千张不同的 iCloud 图片及一小时内存高水位需要真机复测。[第 500 张原始事件](../.local-test-data/performance-fixes-20261121/wall-probe-500.txt) · [第 5,000 张原始事件](../.local-test-data/performance-fixes-20261121/wall-probe-5000.txt) · [UI 结果](../.local-test-data/performance-fixes-20261121/deep-wall.xcresult) · [独立探针改动](../.local-test-data/performance-fixes-20261121/deep-wall-probe.patch)

## 地球转动、松手和近景照片

手指拖动或方向键转动时继续合并相机提交。一段连续操作只在第一个输入样本撤销旧照片查询。沿用现有的 30 Hz 提交上限和标记预算。此前 50、783、3,000 次到访的模拟器对照没有显示到访数增加会同步拖慢相机提交。新变化发生在松手以后。近景用同一 SQLite 游标先交付最早一批通过原生投影的记录，数量显示为预览；精确总数和最终图钉随后发布。城市成员在 SQL 内过滤，镜头、权限或代次失效会撤销旧结果。底图预取最多等两秒，随后交给原生地图继续加载。

| 同一视野，三轮中位数 | 1 万项 | 5 万项 |
| --- | ---: | ---: |
| 新路径首批 48 条可以请求图片 | 12.6 ms | 44.0 ms |
| 同一遍读取完成准确计数 | 45.3 ms | 200.0 ms |

计时从开始读取冻结视野算起。地球仍有一次约 850 ms 的停稳防抖，缩略图出像素和 MapKit 加载瓦片另计。此前 5 万项只在遍历全部结束后交付，约 203 ms。图钉预算与底图上的实际 GPU 帧间隔需在电视上分别观测。[密集视野三轮结果](../.local-test-data/performance-fixes-20261121/near-metadata.txt)

## 从当前画面和整库开始放映

当前画面墙复用已在屏内且通过投影的记录，最多对同次到访的三张候选同时取分析预览。枚举完整固定范围与开场并行。整库和城市在独立读版本中使用日期与照片 ID 游标，首批直接读取，避免开场前另写全量选片表。权限、相册排除和去重继续参与选片。放映可延续原墙的读版本，同时解除对主索引 WAL 的占用。

| 取到首批所用的时间 | 1 万项 | 5 万项 |
| --- | ---: | ---: |
| 整库，独立快照及前三条元数据 | 6.0 ms | 30.0 ms |
| 单城市，独立快照及前三条元数据 | 4.2 ms | 27.3 ms |
| 当前画面，以已确认记录产生开场候选 | 22.7 ms | 0.6 ms |

表中是最终版本一次规模探针，当前画面的模拟记录没有对应的 PhotoKit 图片。前次 5 万组约 3.12 秒花在准备范围。新路径允许在后台全量投影结束前出现开场候选。带公开 Demo 图片的遥控器 UI 测试另外记录了首张确实显示的时间，含 3.4 秒地球片头、1.2 秒章节标题和 XCTest 观察开销。当前画面墙 7.38 秒，整库 7.62 秒。另在 1 万和 5 万固定墙挂载真实放映视图，开场前三项使用本机示例图片。从启动到首图就绪分别为 5.26 秒和 4.75 秒，后跑的一组复用了进程和图片缓存。[规模探针](../.local-test-data/performance-fixes-20261121/slideshow-metrics.txt)

## 最终验收

- 面向 Apple TV 的 Release 构建成功。tvOS 27.2 模拟器从产品入口运行整套单元测试和三条 UI 流程，结果包记录 464 项通过、0 项失败、2 项因依赖私有图库而跳过。三条 UI 分别覆盖第 48→49→48 张并恢复焦点、欢迎页进入示例，以及慢图下载时仍能滚动并移动焦点。[集成结果](../.local-test-data/performance-fixes-20261121/integration.xcresult)
- 另外跑了深页往返、三条地图交互和两条放映遥控流程。地球从卫星进街区再返回、图钉总数与冻结墙一致、快速换城市后成员正确均通过。地图回看墙放映退出后回到原照片。[地图 UI](../.local-test-data/performance-fixes-20261121/near-ui.xcresult) · [放映 UI](../.local-test-data/performance-fixes-20261121/slideshow-ui.xcresult) · [万级墙放映呈现探针](../.local-test-data/performance-fixes-20261121/slideshow-mounted.xcresult)
- 本轮未安装真机。真实 iCloud 下载量和延迟、电视 GPU 帧间隔以及长时间播放的进程内存高水位仍待实测。
