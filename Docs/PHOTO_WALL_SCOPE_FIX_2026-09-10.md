# 照片墙范围与分类一致性修复

日期：2026-09-10。用户目标：查看当前区域、国家或城市时，只展示该目标范围的照片；切换目标不能继续展示旧批次。

## 已确认的问题

1. 当前区域照片墙原来只用 `EarthViewport` 的保守地理圆及可见半球筛选，没有原生屏幕矩形检查。处于地球正面但落在电视画面之外的照片也能进入墙。
2. 开墙时使用 `experience.currentViewport`；快速移动后，它可能来自估算范围，不是点击瞬间实际呈现的 MapKit 画面。
3. 国家／城市墙先从界面取得地点 ID，再异步创建 SQLite 读快照。两者之间发生索引重建时，可能使用不同版本的地点成员。旧加载任务在 generation 检查前写入 reader／摘要，也存在串用状态的风险。
4. Debug Simulator 曾在真实照片 ID 缺失时，把其他模拟器图片确定性映射为替身。这会破坏图片与日期、坐标的对应关系，并造成重复图片的错觉；真机和 Release 原本没有此逻辑。本次所有构建统一只请求准确 PhotoKit ID。

已用实际 MKMapView + SQLite 写出失败用例：屏幕上方 120 pt 的地表照片能通过旧球面筛选，旧墙同时返回 `outside` 与 `inside`，预期仅 `inside`。证据：`.local-test-data/wysiwyg/validation/Reproduction.xcresult`。这些是确认的实现缺口，尚不能单凭自动化认定用户真机“相同的一批照片”的所有触发条件。

## 当前区域：以点击瞬间的原生投影为准

- `PhotoWallViewportCapture` 弱引用首页／探索共用的 MKMapView。中键松开时立即捕获实际相机、bounds、原生投影身份和保守候选范围，与底部照片带的防抖及抽样缓存独立。
- 暂停地球输入并让应用相机采用已呈现的原生相机，放弃未画到屏幕上的输入。照片墙期间阻止滞后的 SwiftUI 相机提交改变地图；关闭后释放捕获，原地恢复操作。
- SQLite 按 RTree 范围读取稳定时间倒序候选，一批最多解码 512 条，另外最多读取一条 lookahead。`PhotoWallPageSelection` 使用每张照片真实 GPS 做屏内投影、背面剔除和回投校验，一页最多 48 张。
- 下一页 offset 计入所有已检查的候选，包括屏外记录；不跳过尚未处理的有效照片。空批次存在后续时保留“继续寻找照片”，不在首屏自动扫完整个世界。
- 不复用底部照片带最多 144 条候选／18 条结果的代表抽样。墙可通过分页遍历范围内全部匹配记录。
- 投影、地图身份或捕获生命周期变化后旧快照失效，终止该范围读取并提示返回重新圈定，不偷偷改用估算圆或别的区域。
- 示例照片墙与 SQLite 墙共用最终原生过滤规则。原有数据库球面查询 API 保留给底层查询与历史回归，正式开墙入口使用 `PhotoViewportSnapshot` 重载。

## 国家、城市与具体到访地点

- 国家和城市选择保存语义范围，在照片分页所用的同一 WAL 读事务内重新确定成员。国家匹配国家名；城市同时匹配国家和城市名，避免不同国家的同名城市串图。
- 一次打开后的成员、排序和分页数据库版本固定。完整分类标签同样跟随该快照，不被后续扫描重分类改成另一个国家的标题。
- 具体到访地点要求该 ID 的坐标依据仍一致；发现重用或消失则提示重新打开，不展示另一个地点。
- 未知／匿名城市和缺少国家的城市按各自地点保留，不因为共享兜底名称而合并。
- 切换集合重建墙的视图身份和分页状态；异步任务在写回 reader、成员摘要、照片和地名之前验证 generation 与取消状态。

分类仍依据聚类中心的 MapKit 城市／国家解析。这里修复的是查询目标和照片所属地点的一致性，没有引入行政边界数据，也没有逐照片反向地理编码。国界／城市边缘的照片可能受既有约 30 km 聚类规则影响；尚未解析出的地点继续留在“地名待完善”，不能宣称每张照片都已通过行政边界认证。屏幕投影也不声称解决真实地形遮挡。

## 数据核对与验证

对本轮前已授权取得的真机 SQLite 副本做只读聚合核对：22,730 张照片，无悬空地点关联，无地点照片计数差异，无归属其他地点的封面。22,722 张照片距所属地点中心不超过 30 km，另外 8 张处于 30–60 km，没有超过 60 km 的记录。此检查不能证明行政边界或当前真机每张图片正确；输出仅含计数，不含私人照片 ID、地名或精确坐标。

没有清除或重建用户索引，不需要用户重新扫描才能使用新范围筛选。真机安装／启动不等于已验收用户实际遥控器快速转动、个人照片内容或大范围原生投影耗时，仍需设备实际观察；既有 MapKit 影像／残影问题不在本次修复范围。
