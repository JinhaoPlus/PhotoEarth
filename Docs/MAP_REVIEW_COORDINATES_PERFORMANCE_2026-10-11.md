# 地图回看坐标与性能排查 · 2026-10-11

本轮修复在本地、tvOS 26.5 模拟器与 tvOS Release 无签名构建中验证。没有安装或运行 Apple TV 真机新版本。

## 已确认的问题与修复

1. **聚合位置不是拍摄位置。** 流式聚合原来累计平均经纬度，屏幕聚合又累计平均投影点并反算 GPS。沿海、跨海或分散拍摄点的平均位置可能落在海上；它与封面照片的 GPS 也可能不一致。现在同一单元保留代表照片的原始 GPS 与资产 ID；合并多个单元时继续采用同一成员的封面和 GPS。范围、全部成员与数量另行保留。SQLite 与示例查询按时间倒序、ID 升序选取代表照片，实际视野流使用同一稳定读取顺序。
2. **多图钉的屏幕布局发生偏移。** 上一版 `TimelineView` 内多个 `.position` 视图没有明确共享的布局坐标原点。相同巴黎测试数据的新旧 4K 截图中，第二、第三个图钉偏离实际地标，第一组仍可看似正常，因而仅检查“图钉会移动”的旧用例未发现错误。现在照片图钉直接采用 `MKAnnotation` / `MKAnnotationView`，MapKit 在地图自身坐标空间中管理位置、相机运动和屏外内容；已移除每帧 SwiftUI 定时重投影和屏幕点反算锚点的路径。
3. **合并超过 32 组的计算量过大。** 原算法每合并一次重新穷举全部点对，240 组减到 32 组时该阶段最多约 230 万次点对比较。现在保留数量最多的 32 组，其余分配到最近的保留锚点，该阶段最多 208 × 32 次比较。100 pt 邻近／传递重叠合并仍保留。全部成员和计数不丢弃；封面请求仍最多 32 个。
4. **旧任务清理可能关闭新读取游标。** 新视野与已取消视野共享固定 WAL 读取器，旧任务异步结束时原来会无条件清理当前计数游标。现在连续计数游标有 operation ID，取消、异常和结束只清理所属游标。补验迟到的旧结束、旧取消调用与默认结束调用都不能关闭新任务游标。

PhotoKit 扫描直接读取 `asset.location.coordinate`；SQLite 写入与读回的纬度／经度顺序一致。未发现自行坐标换算或经纬度交换。没有添加地区坐标补偿，没有修改用户照片元数据。首页地点柔光仍表示访问摘要，使用地点中心；它与地图回看中表示具体照片的图钉语义不同。

## 验证与资源边界

- 最终 49 项相关单元测试通过：地图回看、SQLite 分页／连续计数、原生地图可见性、冻结投影、间接触摸。原生标注对齐用例额外覆盖五组坐标：巴黎、上海、悉尼、日期变更线及高纬度。
- 对齐检查包含地图容器原点偏移、方向移动、地图／卫星切换和缩放；标注 GPS 与源记录完全相等，视图中心与原生地图投影相差小于 2 个逻辑点。该容差用于原生布局取整；日期变更线曾测得约 1.1 pt 的差异。
- 3 条 UI 流程通过：原生照片图钉持续移动、Play/Pause 工具条与样式切换；三次无照片区域往返及准确总数／空状态；跨 48 张分页的详情和逐层返回。已复核 3840 × 2160 截图中的地标位置、封面、数量角标、照片条及法务净空。
- 保留至多 240 个轻量单元、32 个原生图钉、48 条当前分页记录；SQL 每批至多 512 条，严格投影缓存最多 1024 个坐标。移动时保留既有原生标注，不重新聚合、不启动全库图片请求；停稳后完整新批次替换，包括空批次。
- Release tvOS 无签名构建通过。未进行真机安装、启动或遥控器体验验证。

## 性能结论的边界

基准使用模拟器 Debug、合成元数据，只测流式聚合、可见单元合并和 SQLite 读取。聚合计时已将测试记录创建移到计时之前；此前约 57–66 ms 的初步值包含创建记录的时间，不作为纯聚合耗时。SQL 聚合为初始镜头范围查询；连续 SQL 计数不含原生投影、PhotoKit 图片下载或地图影像下载。数值不能代表 Apple TV 的帧率、内存峰值或真实大图库下载表现。

尝试使用 Instruments Time Profiler 附加模拟器应用，记录停在附加阶段，没有取得可用 CPU 样本，已结束该记录进程。因此本轮不宣称完成了 Instruments CPU／帧率分析。用户报告的具体照片尚未逐张在真机核对；若原始照片 GPS 本身存在误差，需要另行对照 PhotoKit 的原始元数据。
