# Photo Earth 旅途、地球与放映重构验收

本文的 Top Shelf 截图及完整旅程回执记录此前的真机版本。后续版本改为复用首页的最近到访城市。[当前主屏规则](TV_TOP_SHELF_JOURNEYS_2026-11-19.md)

用户于实施中将后续验收改为「客厅」实体 Apple TV，以降低 Mac 负载。设备是第三代 Apple TV 4K，tvOS 27.2.1，通过局域网配对。显示输出为 3840 × 2160。开发构建使用 Xcode 27.2，最多两个并行任务。私有截图、录屏和测试结果保存在项目本机的 `.local-test-data/earth-20261119/`。

## 实现入口

| 用户动作 | 实现和门禁 |
| --- | --- |
| 首次授权、排除相册、恢复扫描 | 普通相册先取成员并集。扫描按互斥原因记录每个唯一素材，识别到缺失相机证据时排除，证据未知时保留并计数。权限或排除范围收窄时撤下旧结果。代码与状态门禁见[扫描验收](JOURNEY_SCAN_VERIFICATION_2026-11-19.md)。 |
| 浏览旅行、城市和详情地址 | 使用 LensPin 的目录和城市身份、国家推断及相邻同城归组规则。最近到访保留原始访问。详情单独读取该素材的 Photos 缓存地址并再次核对位置，照片无有效缓存时保留坐标。Photos 的地址缓存字段属于未经公开保证的运行时接口，系统升级及审核兼容性需要独立评估。 |
| 从地球放大到街区 | 用同一张原生地图在实际距离越过 800 km 时交接地球亮点和按 GPS 聚合的照片图钉；镜头、反向缩放、当前城市范围及遥控焦点沿用原上下文。[地球实现与测试](GLOBE_SCALE_IMPLEMENTATION_2026-11-19.md) |
| 从首页或照片墙开播 | 首页使用整个合格图库，照片墙使用进入时冻结的范围。会话以稳定分页游标轮换到访地点，用跨页画面指纹和 Vision 相似度去重，在同组内优先选画质较好的素材。静帧可见、视频首帧就绪、实况开始播放后才记入已播。前台播放期间维持屏幕常亮，暂停和离开时恢复系统设置。[分页状态机](../PhotoEarth/Domain/Slideshow/SlideshowPageSequence.swift) · [放映协调器](../PhotoEarth/Features/Slideshow/EarthSlideshowCoordinator.swift) |

## 切换到真机前的证据

从 Mac 的真实照片库按拍摄年份读取 2024、2025、2026 三个自然年的 28,294 个照片及视频候选。在独立模拟器中导入了首批 2,217 项，其中 1,629 张普通照片、588 张 Live Photo。按唯一资产读回，1,684 项有定位；7 个相册的成员关系吻合。修正系统导入时重读原始时区产生的日期偏差后，拍摄日期、GPS、收藏、媒体种类和相册成员对账通过。系统 PhotoKit 批量查询曾多返回两条重复行，产品和验证工具均按资产 ID 去重。

2,217 项样本的放映进行到 26 分 19 秒时按用户指示停止，已有 201 个实际呈现记录，201 个唯一素材。Mac 后续云端采样随之停止。完整的 5,000 项模拟器和一小时模拟器测试未执行到底。公开样例的图钉合计、胶片和冻结照片墙均为 9；冷地图瓦片超时及切换视觉的复核见地球文档。50,000 条确定性索引测试在该开发环境的单次写入为 0.811 秒，查询为 0.029 秒。该组数据用于验证规模和正确性，无法代表电视读取 iCloud 媒体的耗时。

从 Cloudflare 取得的版本为 `ne-geonames-cnjpus-20261022.1`，28,096 条，3,578,595 字节，与 App 内置资源的 SHA-256 一致。直接编译两项目的匹配器，针对 1,246 个公开坐标、8 种语言的 9,968 组输出一致。[比对方法及结果](JOURNEY_SCAN_VERIFICATION_2026-11-19.md)

## 实体电视

调试使用「客厅」的实际系统图库。首次连接时设备处于休眠，用遥控器唤醒后进入应用。按最新安装约定，每次换开发版本都先卸载 PhotoEarth、核实目标包已消失，再安装新包。大图库验收使用电视自己的 Photos。用于稳定复现焦点和布局的 UI 用例另有固定示例旅程。

电视上的旧索引中，照片、访问和旅程表都为空。重新授权和扫描后，从电视读回 SQLite 并进行一致性检查。首次取样时，55,987 条唯一资产有扫描归因，其中截图／录屏 2,939 条，无定位 22,528 条，纳入旅途 30,520 条。纳入的素材分为 9,879 张静态照片、19,282 张 Live Photo 和 1,359 个普通视频，对应 783 次原始访问和 27 趟旅程。这份索引涵盖 14 个拍摄年份，已有 23 个非空国家标签；各访问的素材计数逐一与成员对账相符，孤立素材为零。相机证据首轮已检查 2,943 项，其中 3 项确认有相机信息，2,940 项尝试过但仍未知。另有 27,577 项尚未检查。放映至第 20 分钟时再次从电视读取账本，完整性检查通过。30,520 项均已尝试检查，其中 144 项确认有相机信息，30,376 项仍未知，确认无相机信息为 0。约 99.5% 的定位素材当时缺乏可用的本机相机证据，因此这项过滤在这台电视上的实际剔除贡献为零。未知包含多种原因，不能一概解释为 iCloud 原件未下载。

### 一小时连续放映

从「客厅」首页单击「地球放映」，真机 XCTest 在第一个真实素材出现后计时 3,600 秒，持续检查前台状态、实际媒体、重试及重播界面。首帧与末帧相隔 **3,603.11 秒**，实际呈现 **463 个素材，463 个唯一素材**。相邻素材呈现间隔中位数为 **7.20 秒**，最大为 **18.26 秒**，包含实况、视频和章节切换所用时间。账本逐项验证了连续序号和会话内资产去重；视觉相似度另按上面的真实手标样本核验。

约每分钟从设备读取一次缓存文件大小，57 次采样中正式旅行索引 WAL 始终为 0 字节，相机检查账本 WAL 最大 4,091,192 字节。Instruments 的无线采样连接提前断开，这次一小时运行没有可靠的进程内存峰值。后续 Debug 实际呈现账本会按固定间隔附带进程内存和驻留条目计数。

本机证据目录为 `.local-test-data/earth-20261119/television/`。完整长播结果见 `verified-final.xcresult`，逐项呈现见 `tv-hour-presentations.jsonl`，统计见 `tv-hour-verification.json`。可用 `python3 Scripts/verify_tv_slideshow.py <账本路径>` 独立重算。每场运行使用新的随机密钥，记录只含当场有效的素材摘要。
