# 单一离线地名库

Photo Earth 与 LensPin 从这一版起只随包提供一个地名数据库 `WorldCityAtlas.sqlite`。照片扫描、地点显示、示例地点以及 Photo Earth 的 Top Shelf 共用它。地名资料随 App 更新。新版客户端使用相同的 SQLite 文件和查询代码。

| Photo Earth 地名资源（未压缩） | 上一版 | 本版 |
| --- | ---: | ---: |
| SQLite 数据库 | 59,719,680 字节 | 61,849,600 字节 |
| App 内全部地名资料，含署名 | 64,421,090 字节 | 61,855,025 字节 |

SQLite 版本为 `world-atlas-20261121.4`，包含 190,521 个地点。旧底表的 28,096 个代表坐标和 47 条同城别名已并入数据库。别名坐标保留在原地，城市显示、旅程归组与货架标题使用稳定的规范 ID。对于原始数据缺地区码的 12 条记录，显示地区和坐标归属证据分别保留。这样原先靠史料、点位或边界确认的城市不会因显示码补全而改变匹配顺序。

匹配在设备端使用这份库的市镇界、国家或地区边界及城市代表点。只确定国家时显示国家，无法确定地点时保留真实照片坐标。地名的语言与地区按库里的词条处理，仍可用已有名称显示缺少本地译名的城市。图库内容继续只读。

构建源 TSV 固定在 LensPin 的版本目录，供重建追溯。Photo Earth 的两份旧表和目录清单已从应用移除。新版应用已移除历史下载的客户端读取和定时检查，也清理安装前遗留的公共目录下载缓存。LensPin 设置移除了手动更新入口。历史发行文件继续留在版本目录。

新版 SQLite 两次独立生成逐字节相同，SHA-256 为 `0410658ce39eeeae436e4da60b578e208b4f368c0970848a96d33a28e68ee090`。[构建输入与校验步骤](../../../camera_photo_geo/CityResources/WorldAtlas.md)

## 验证

- 以 .3 的实际发布代码冻结旧结果。两个产品分别回放 1,258 个公开坐标的八种语言和 56,191 个密集英文点，各比对 66,255 组。城市 ID、城市名称、地区标识、地区名称和来源逐项一致。
- 72 个旅行城市中心和 217 个独立景点全部通过。优先目的地的 2,177 点逐行核对与上一版一致。
- 全库 190,521 个地点在八种基础语言和三种繁体地区设置共 2,095,731 个显示值，主 App 和 Top Shelf API 均逐项与上一版一致。
- tvOS、iOS 模拟器和 macOS 构建内各找到一份 SQLite，文件哈希相同。两份历史 TSV 和旧清单均已退出构建包。

[逐项统计与哈希](WORLD_CITY_SQLITE_VALIDATION_2026-11-21.json)

tvOS 的八语首页与遥控器测试通过。涵盖地名、索引恢复、缓存、Top Shelf 和本地化的 tvOS 专项验收通过 80 项，补加旧下载清理后另跑 16 项相关测试，均通过。LensPin 最终单库验收在 iOS 模拟器通过 15 项，macOS 通过 4 项。三个构建均未用于真机安装或发布。
