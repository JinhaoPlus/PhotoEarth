# 手势精简实施约定：真机轻触外圈漂移

状态（2026-09-09 最新反馈）：用户确认整个 touchpad 拖动必须保留，且 Liquid Glass 缩放工具条显示时也要继续拖动。首次精简的 Game Controller 能力门控过严，可能把拖动整体关闭；工具条暂停全部输入也增加了操作往返。本次统一使用 UIKit 间接触摸生命周期，并把工具条内的触摸拖动与按键 Focus 分开，验证结果另行补充。下文保留旧识别器的合成复现与首次精简证据；它们不能代替此次修订或真机手感验收。

## 已接受的选择

取消圆环旋转缩放和中键双击。整个触摸面只负责拖动，缩放集中到底部原生 Liquid Glass 工具条。工具条打开后仍能直接拖动地球，实体左右按键选择缩放按钮，中键执行按钮。保留物理方向键、中键短按/长按和逐级返回。

这必须与落指、微抖、按压和抬手仲裁一起调整。单独把外圈也改成拖动，轻触仍可能移动相机，不能算解决漂移。

## 修改前逻辑（历史基线）

| 输入 | 当前行为 | 歧义或代价 |
| --- | --- | --- |
| 内侧触摸滑动 | 绝对坐标差驱动 pan，累计 0.004 即可起动 | 落指过渡、微抖可能直接移动 |
| 外圈触摸滑动 | 半径 ≥0.60 候选，累计 0.045 rad 激活，之后 0.002 rad 即输出缩放 | 与 pan 共用坐标，最初几个样本决定整次接触含义 |
| 外圈实体方向按压 | 小步、长按加速、释放动量/补步 | 按压与坐标分别回调，需要明确所有权 |
| 中键短按 | 松开后等 350 ms，再开照片墙 | 为双击付出固定等待 |
| 中键双击 | 以当前中心放大约 2.4 倍 | 与单击/长按共享时间判定；没有对称的直接缩小动作 |
| 中键长按 | 650 ms 后开缩放与帮助面板 | 已有明确缩放入口，但当前大面积遮黑不适合频繁调整 |
| SwiftUI 方向事件 | onMoveCommand 提供降级 nudge | 与 Game Controller 通过时间窗口去重，是同一操作的另一条输入路径 |
| 无可靠触摸生命周期 | 位置推断接触，450 ms 无活动才释放 | 快速抬手重落可能沿用旧锚点 |

`receiveTouchContact(true)` 在无飞行时已经调用 markInput，尚未确认移动也会撤销 ready 照片带。接触状态和实际操控应分开。

## 修改前生产识别器复现

证据：`.local-test-data/gesture-simplification/RecognizerProbe.swift`、`recognizer-output.txt`、`README.md`。只编译正式识别器并输入合成坐标，没有修改生产代码。

1. **落指中间位置成为拖动起点。** 显式 touch-down → `(0.10, 0)` → `(0.80, 0)` 输出 `pan dx=0.70`。`RemoteSurfaceGestureRecognizer.update` 只凭之前坐标半径大于 0.06 就锁 pan，没有要求此前已经确认拖动。若首样本是 `(0, 0)`，相同外圈终点却会进入 ring。错误初判同样会被锁定，直到抬手。
2. **外圈微移产生正反缩放。** `(0.80, 0)` → `(0.80, 0.04)` 已变化约 2.86°，超过 2.58° 起动阈值；回到原位立即发反向缩放。这证明算法接受该扰动，实际遥控器噪声幅度仍未知。
3. **快速重落沿用旧 pan。** 无显式 touch-up 时，旧终点 `(0.45, 0.10)` 后在 450 ms 内重触 `(0.80, 0)`，输出 `pan(+0.35, -0.10)`。若中间有 neutral，再在另一边落指，可出现更大错误位移。缺少真实释放信号时，它与连续拖动无法可靠区分；缩短超时只会改变风险窗口，并可能打断慢拖。

前两条不依赖退化硬件。第三条只属于无可靠 touch-up 的路径，尚未确认用户设备实际采用哪一种。上一轮测试覆盖超时后重落、有效快扫不丢样等正常路径，没有充分覆盖意图判定歧义，因此自动化通过不足以证明真机稳定性。

## 方案比较

| 方案 | 获益 | 代价 | 选择 |
| --- | --- | --- | --- |
| 整个触摸面只拖动，显式 ± 缩放 | 消除内外圈动作分类，滑动含义一致 | 缩放多一次进入控件 | 用户已接受 |
| 先进入缩放状态，再启用圆环 | 拖动与圆环不再同时候选 | 仍要记模式、半径、顺逆方向和设备差异 | 不进入首轮简化 |
| 完全按键 | 易控制误触、兼容性最好 | 失去直接把玩地球的感觉 | 仅没有触摸硬件时降级；不能用于现有 touchpad |

Apple 的遥控器指导提醒拇指搁置、拿起遥控器时可能产生非意图 tap；手势指导要求自定义动作易发现、彼此可区分，并提供替代入口。它们支持减少默认隐式分类，具体映射是本项目已接受的设计决定。[Remotes](https://developer.apple.com/design/human-interface-guidelines/remotes)、[Gestures](https://developer.apple.com/design/human-interface-guidelines/gestures)。

## 正式操作映射

| 操作 | 当前约定 |
| --- | --- |
| 轻触、搁住、落指微抖 | 相机不动；不因单纯接触隐藏照片或发起查询 |
| 明确滑动，包括外圈区域 | 只拖动地球，地表同向跟手，松手即停 |
| 实体上下左右 | 按下一次先小步旋转，持有约 180 ms 后持续旋转；松开无惯性、无补步 |
| 中键短按 | 松开立即进入当前范围照片墙，不再等双击窗口 |
| 中键长按约 650 ms | 打开底部原生 Liquid Glass「缩小／放大／完成」；继续触摸拖动，实体方向交给工具 Focus；松开不再开墙 |
| 工具条内滑动 | 继续同向拖动地球，不移动工具按钮 Focus |
| 工具条选择 ± | 实体左右选择、中键执行；围绕当前中心平滑缩放，反向立即响应，边界不播空动画 |
| Back | 工具条内先关闭工具条；其它场景仍按四层导航逐级返回 |

取消默认双击，不用另一个复杂组合键补回。Play/Pause 保持播放用途预留，不再增加缩放入口。原先全屏遮黑 68% 的帮助面板收为轻量底部工具条，缩放时仍看得清地球。工具条使用 tvOS 26 的 `GlassEffectContainer` / `glassEffect`，与首页玻璃 Dock 保持一致；保留冷白色文字、克制胶囊轮廓和清楚的 Focus，为底部 MapKit 署名至少留出 88 pt 净空。Reduce Transparency 使用深色实底，Reduce Motion 简化焦点与进入动效。

## 本轮实施规则与参数

- UIKit 真实 began 与首次 moved 建立落点，这一初始段不移动相机，也不在起动时回放；之后才累计明确拖动意图。首次落点预留给触摸通路，不把单纯接触当作相机运动。
- 起动门槛与已确认拖动的连续灵敏度分开。当前 UIKit 意图距离为 12 pt；基线后的位移与落点总位移均达到门槛才起动。未确认单步超过 120 pt 优先视为落点跳变，连续同向且量级相近的大步保留快扫识别通路。已确认后不再重复门槛或逐样本截断，按窗口短边的一半归一化有效位移后送入 30 Hz 相机帧循环。最初段被有意舍弃，参数仍需真机静置、慢拖与快扫校准。原 GC 坐标通路的 0.06 / 0.24 参数属于首次精简历史，不作为 UIKit 点坐标门槛。
- 一次接触只有一个所有者。实体按压后锁定按键操作，释放按键不能自动接回旧 pan；重新落指才开始新拖动。工具条中继续拖动，实体方向与中键只操作按钮。只有照片墙和详情完整暂停地球输入。
- 接触不等于操控。轻触最多显示提示，不能自动启动相机循环、取消照片查询或撤销 ready 批次。
- UIKit `.indirect` 的真实 began/moved/ended/cancelled 是唯一拖动来源，Game Controller 只负责实体方向和中键。不能因 Game Controller 缺少独立触摸接口就禁用拖动，也不能把同一次位移重复提交；不再用 `isTouched` 或 450 ms 超时猜测抬手。独立触摸桥在整个探索场景持续安装，包含 Dock 显示与退场期间；它不依赖地球 Focus，不继承输入面无障碍节点，并阻止同次拖动同时改变工具条 Focus。
- Debug 诊断只记录输入通路及必要能力，不记录触点、照片 ID 或精确地理坐标。实体 cardinal 可用时避免重复 UIKit 方向；工具条内方向只交给原生按钮 Focus，不得流入地球转动。

## 本轮验收要求

1. 真机不同位置轻触/搁置/拿起遥控器共 100 次，相机无非意图位移或缩放，照片带不反复消失。
2. 覆盖内外区域落指、微抖、按压前后错序、快速抬手重落、过中心和抬手回零；每段接触只产生一个明确操作。
3. 慢拖、小幅反向、快扫仍跟手，起动门槛只用于意图确认，不吞已确认位移。
4. 短按松开立即开墙，长按只开工具条；工具条内继续触摸拖动，按钮 Focus 不跳动，实体方向和中键不串地球动作；Back 返回正确。
5. 验证方向单击只走一步、持有约 180 ms 后持续转动、松开无尾部位移；有 touchpad 时不能因为 GC 能力检测而失去拖动；没有触摸硬件时仍可完成四层导航与工具缩放。
6. 在电视观看距离审视原生 Glass Dock：地球保持可见、按钮和 Focus 清楚、法务署名无遮挡；Reduce Motion 与 Reduce Transparency 路径均可用。
7. 补充上述歧义的自动化回归；实体遥控器仍须复验，不能由合成测试替代。

## 2026-09-09 恢复拖动与工具条持续操控

最新实现统一到 UIKit 间接触摸生命周期，不再靠 Game Controller 是否暴露独立触摸接口决定能否拖动。工具条打开只切换方向键和中键的路由；相机中心、距离与触摸拖动保持连续。玻璃 Dock 增加「滑动拖动地球」提示，保留现有风格和署名净空。

当前修订完整 139 项单元、5 条 UI 导航均有最终通过证据，截图与构建已复核，并于 09:33 安装到 Apple TV、以前台 Demo 启动。最终结果及原始失败记录见行动计划末尾，证据位于 `.local-test-data/live-zoom/validation/`。模拟器 UI 仅能核验物理方向、按钮和导航；实际慢拖、快扫、按压后重落、边拖边缩放与松手停止须由实体遥控器复验。

## 2026-09-09 真机发现滑动仍切换工具按钮

用户实测确认上述触摸识别器竞争未能阻止原生 Focus。当前工具条改由局部公开 Focus 环境拒绝方向寻址，只有真实左右按压向原生按钮发出明确焦点请求；窗口触摸采样持续服务于地球拖动，不再通过识别器类型、触摸数量或按压时间窗口推断来源。具体实现、自动化证据与真机交付状态见 [缩放工具条焦点修复](ZOOM_FOCUS_FIX_2026-09-09.md)。此前按键 UI 测试通过不能作为实际滑动不切按钮的证据。
