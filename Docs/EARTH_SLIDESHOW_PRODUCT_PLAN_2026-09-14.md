# Photo Earth「地球放映」产品与实现方案

状态：首版已实现；2026-09-15 完成连续播放、电影感与无文字沉浸层调整，真机与真实 iCloud 混合图库仍待验证

本文记录 9 月首版。后续开发采用单一「地球放映」入口与持续选片规则，见[11 月改造方案](JOURNEY_SCAN_AND_LONG_SLIDESHOW_PLAN_2026-11-19.md#4-长时间大范围去重的地球放映)。

日期：2026-09-14

适用范围：首版地球放映的产品、设计、数据、媒体、性能与验收边界

## 1. 产品决定

Photo Earth 增加用户主动触发的「地球放映」。它不是在照片之间随机套用特效的普通幻灯片，而是一段由地球负责地点与章节、由真实照片负责情绪内容的私人旅行短片。

首版聚焦由照片墙明确冻结的观看单位：

- 一次独立到访。
- 一座城市中按时间分开的多次到访。
- 一个国家内按时间排列的多座城市与独立到访。
- 用户在探索地球上圈定的当前可见照片范围。

一次默认放映约 2–3 分钟，最多包含 24 个不重复的回忆项。放映按时间从早到晚展开；同一城市的多次到访分别成为章节。主地球继续不绘制地点连线、旅行路径、道路标签或 POI 文字。

相似照片去重和多样化转场属于首版质量门槛，不作为后续可有可无的增强：

- 去重必须保守，宁可放过少量相似照片，也不能错误隐藏真正不同的记忆。
- 转场必须根据时间、地点、媒体和构图关系选择，不做无意义的完全随机播放。

## 2. 核心体验

用户从最近到访、城市、国家或当前地图范围照片墙选择「地球放映」后，经历以下完整流程：

1. 照片墙和控件逐渐退场，同一个常驻 MapKit 地球成为全屏主角。
2. 地球从近轨道取景飞向本次到访的真实区域。
3. 克制显示城市、国家、完整到访日期和本次精选数量。
4. 按拍摄时间从早到晚播放照片、Live Photo 与短视频片段。
5. 城市存在下一次独立到访时，照片退场，重新露出地球；地球拉远并转向下一章节。
6. 最后一项结束后回到近轨道地球，以实际索引数据呈现安静的收束信息。
7. 用户选择重播或返回；返回后恢复来源照片墙，并把 Focus 放回最后实际观看的照片。

建议的章节标题只陈述事实，例如：

> 东京
>
> 2019年4月12日—4月18日 · 8个精选瞬间

不根据有限数据虚构「第一次抵达」「蜜月」「毕业旅行」等人生语义。只有未来具备可靠来源或用户明确编辑后，才可以显示这类描述。

## 3. 首版范围

### 包含

- 最近到访中的单次访问放映。
- 城市照片墙中的多次到访章节放映。
- 国家照片墙中的代表性多地点章节放映。
- 当前地图画面照片墙中的可见范围精选放映。
- 默认「精选放映」：合并相似照片，最多 24 项。
- 次级「完整放映」：保留相似照片，继续按稳定时间顺序分页播放。
- 地球开场、章节间地球转场和地球结尾。
- 静态照片、Live Photo 和普通视频。
- 可选 Apple Music 配乐：仅在用户主动连接、授权且当前订阅可播放目录内容时开放，并允许用户选歌。
- 可中断、可暂停、可跳过和可逐级返回。
- Reduce Motion、VoiceOver、后台、图库变化及 iCloud 弱网处理。

### 暂不包含

- 脱离照片墙成员范围的全球图库一键放映。
- 依赖当前 `TravelJourney` 自动推断生成跨城市「完整旅程电影」。
- 手工时间线、剪辑器、字幕编辑、模板商店或转场选择器。
- App 自带固定配乐库、音乐下载／导出、节拍分析、精确同步卡点或额外音乐版权处理。
- 导出、分享或生成应用私有视频文件。
- 对全量图库预先生成视觉特征。
- 把图片特征、相似分组或放映计划写入 iCloud KVS。

这些边界让首版不依赖尚未稳定的跨编辑旅程身份，也避免为了一个观看功能扫描或下载用户的全部图库。

## 4. 入口与导航

- 每个照片墙标题区提供可见、可聚焦的「地球放映」按钮；遥控器 Play/Pause 可以作为快捷方式，但不能成为唯一入口。
- 默认直接开始「精选放映」，不先展示复杂配置页。
- 「更多放映选项」可以提供「完整放映」，让用户主动保留连拍与相似照片。
- 放映是照片墙之上的临时观看状态，不新增第五个侧边栏入口，也不改变来源页面的成员范围。
- 开始时冻结本次集合成员与数据库读取版本；后台索引更新不能在放映途中重排章节。
- Back/Menu 从任意准备、地球转场或媒体阶段退出，回到原照片墙和最后实际观看项。
- 结束页提供「重新播放」与「返回照片墙」两个标准 Focus 操作；控件淡入完成后才交付 Focus。

## 5. 放映计划

### 5.1 输出结构

建议使用以下纯模型表达一次不可变计划：

```swift
struct EarthSlideshowPlan {
    let scope: EarthSlideshowScope
    let chapters: [EarthSlideshowChapter]
    let mode: EarthSlideshowMode
    let candidateCount: Int
    let omittedSimilarCount: Int
}

struct EarthSlideshowChapter {
    let visit: TravelPlace
    let items: [EarthSlideshowItem]
}

struct EarthSlideshowItem {
    let record: PhotoAssetRecord
    let transition: EarthSlideshowTransition
}
```

模型名称可以在实现中调整，但计划必须与 SwiftUI、PhotoKit 请求对象和播放器解耦，以便确定性测试。

### 5.2 数量与顺序

首版基线集中在一份配置中，不散落在 View：

| 配置 | 初始值 |
| --- | ---: |
| 最终精选数量 | 最多 24 项 |
| 候选分析数量 | 最多 96 项 |
| 开始首章所需 | 6 个不重复项；总量不足时以实际总量开始 |
| 城市章节数量 | 最多 6 次到访 |
| 相似度缩略图 | 384 px 长边、保持方向一致 |
| 视频自动片段 | 最多 12 秒 |

- 单次到访只有一个章节。
- 城市存在超过 6 次到访时，必须保留最早与最近一次，其余按时间跨度选择有代表性的中间到访；不能简单只取最近 6 次。
- 每个入选章节在内容足够时至少得到 2 个回忆项，剩余名额再根据时间跨度、照片数量与内容多样性分配。
- 每章先按时间区间取样，再做质量选择，避免只从最新一页挑选 96 张而漏掉到访前半段。
- 计划最终按 `creationDate` 升序、同时间按稳定资产 ID 排序。相同输入、相同索引版本和相同算法版本必须得到相同章节、照片与转场。

## 6. 相似照片去重

### 6.1 作用域

去重只决定「本次精选放映选择哪些内容」，不删除、隐藏、修改或收藏 Photos 中的任何资产，也不改变照片墙、详情、地点统计和准确总数。

去重分为两个等级：

| 类型 | 判断范围 | 规则 |
| --- | --- | --- |
| 近乎相同 | 整场放映 | 对复制、重新导出、轻微裁切或轻微调色的近重复内容，只保留一个代表项 |
| 相似场景 | 同一次到访内 | 必须同时满足视觉相似、时间接近和位置接近，才把连拍或几乎相同构图合为一组 |

不同到访之间不得仅因拍到同一地标、同一人物或相似构图而合并。这样可以保留「多年后重返同一座城」的变化。

### 6.2 分析流程

1. 先用已有元数据完成时间分桶、章节配额和候选上限控制。
2. 用户明确开始放映后，通过共享图片调度器请求候选的 384 px 缩略图；不把视觉分析加入首次图库扫描。
3. 统一处理图片方向和缩放策略，使用固定 Vision request revision 生成 Feature Print。
4. 新候选只与已经入选的代表项比较，工作量受 96 × 24 的硬上限约束，不对 5 万张图库执行两两比较。
5. 极高相似度使用全场近重复规则；中等相似度只有在同一次到访、拍摄时间相差不超过约 10 分钟且坐标距离不超过约 500 m 时才允许合并。
6. 视觉阈值、时间窗口、距离窗口和 Vision revision 统一放入 `PhotoSimilarityConfiguration`；上述 10 分钟／500 m 是首轮测试基线，不是未经验证便永久锁定的常数。
7. 达到 24 项即停止扩大候选；如果相似组导致数量不足，可以继续读取候选，但最多分析 96 项。

不得使用一个不经样本校准的单一视觉距离阈值。输入方向、缩放方式和 Vision revision 变化都可能改变距离分布；版本变化必须重新跑固定样本。

### 6.3 组内代表选择

同一相似组按以下优先级选出一个代表：

1. 用户明确收藏的资产。
2. Vision 图片美学评分更高且不是工具型图片的资产。
3. 保持整场媒体多样性的 Live Photo、静态照片或短视频。
4. 更适合电视完整展示的构图。
5. 更高有效分辨率。
6. 时间和资产 ID 的稳定兜底顺序。

收藏是用户明确表达，优先级必须高于自动美学评分。动态媒体不能无条件击败更有意义的收藏照片。

### 6.4 失败与降级

- Vision 分析失败：保留候选，并只使用时间／位置的保守连拍降级；不能因没有特征而丢弃照片。
- iCloud 缩略图在截止时间内不可用：继续准备其他候选；当前照片可用时不让整场被一项阻塞。
- 最终不足 6 项但范围已经读完：按实际数量开始，不从城市外补齐。
- 所有候选均不可用：停在地球准备场景，显示真实错误和返回操作，不进入空黑场。
- 被系统或用户删除的资产：立即从尚未播放队列移除；当前资产不可继续时平滑跳到下一项。

### 6.5 隐私与持久化

- Vision 分析完全在 Apple TV 本机进行，不上传图片、特征或相似关系。
- 首版 Feature Print 只在本次放映和有限内存缓存中存在，退出、后台、权限撤销或内存告警时释放。
- 不把 Feature Print、相似组、精确坐标或照片 ID 写入 iCloud KVS。
- 不复制原图、Live Photo 或视频到应用永久存储。
- 如果未来持久化本地特征，必须使用独立可清理表，记录算法 revision，并随资产编辑、删除、权限变化和版本不兼容失效；这一项不属于首版。
- 首次使用地球放映时应以短文案说明：「仅为本次放映在此 Apple TV 上分析小尺寸预览，不会上传或修改照片。」

### 6.6 初步可行性证据

2026-09-14 使用项目内 10 张公开示例图和 Vision revision 2 做了非生产探针：同图距离为 0；一张样片不同幅度的中心裁切约为 0.14–0.35；不相关示例图的最小距离约为 0.71。它只证明原生特征距离值得进入原型，不构成正式阈值、Apple TV 性能或真实家庭图库准确率证据。

上线前必须建立人工标注的固定样本，至少覆盖：完全复制、裁切／调色副本、人物连拍、夜景、烟花、同一景点不同角度、同一城市多年重访、Live Photo 封面与导出静态图、视频封面与静态照片。

## 7. 转场导演

### 7.1 原则

多种转场用于表达内容关系和调节节奏，不用于展示特效数量。`SlideshowTransitionDirector` 根据章节、时间间隔、媒体类型、构图变化和视觉差异确定转场，并使用稳定种子消除无意义的重播随机性。

### 7.2 首版转场语法

| 内容关系 | 转场 | 建议时长 | 约束 |
| --- | --- | ---: | --- |
| 同一天、节奏连续 | 柔和重叠叠化 | 1.0–1.15 秒 | Live Photo／视频前后优先使用 |
| 同章节、时间明显跳跃 | 叠化中的微漂移 | 1.1–1.25 秒 | 位移不超过 16 pt，不产生推页感 |
| 横竖构图发生明显变化 | 叠化中的轻微收束 | 1.15–1.3 秒 | 最大约 1.1% 缩放，不裁切原图 |
| 跨自然日 | 慢叠化与日期印记 | 1.3–1.5 秒 | 日期来自真实拍摄时间，浮在照片左下方，不进入整屏黑场 |
| 切换独立到访 | 照片退场 → 地球桥接 → 下一章 | 2.4–3.2 秒 | 不画路线，不新建第二颗地球 |
| 整场开场／结尾 | 近轨道地球推进／拉远 | 3–4 秒 | 保留 MapKit 法务署名 |

普通照片转场还必须满足：

- 连续内容允许重复使用纯叠化；不得为了展示效果数量或打断三次重复而机械插入推移、缩放等不合适特效。
- 地球只在开场、到访章节切换和结尾出现，不能每两张照片都飞行一次。
- 照片始终按原始比例完整呈现；转场不能把竖图或全景图强制裁满屏幕。
- 不使用立方体翻转、纸张翻页、漩涡、强闪白、持续景深模糊或与内容无关的粒子爆发。
- 首版只使用 SwiftUI 的 opacity、offset、轻微 scale 和既有地球相机能力；不引入全屏自定义 Metal shader，也不为转场启动第二个 RealityKit 地球。
- 缓冲期间保持当前稳定画面，不循环播放等待动画或让黑场无限延长。
- 用户的暂停、跳过和退出输入拥有最高优先级；转场不得阻塞输入。无法平滑暂停的短转场应立即收束到稳定帧。

### 7.3 Reduce Motion

Reduce Motion 开启时：

- 照片之间只使用渐隐渐现或直接切换。
- 取消方向推移、缩放、视差、动态模糊和自动地球飞行。
- 章节仍用静态地球取景、日期文字和淡入淡出表达，不能因为取消运动而丢失地点或时间语义。
- 用户主动开始后仍可以自动前进，并始终提供立即暂停；不自动进入放映。

## 8. 照片、Live Photo、视频与声音

- 静态照片默认停留约 4.5–6 秒，具体值由章节节奏配置决定，不根据随机数改变。
- Live Photo 在用户启动整场放映后可以自动请求并完整播放一次；请求失败时保留静态封面并继续。
- 普通视频默认最多播放开头 12 秒，随后进入下一项；用户可以暂停后选择观看完整视频，但这会暂时接管放映节奏。
- 地球放映默认不自动播放背景音乐；控制层提供「连接 Apple Music」，只有用户明确选择后才调用系统授权，并检查当前 `MusicSubscription.canPlayCatalogContent`。未授权、无有效订阅或服务暂不可用时，照片放映本身始终可继续。
- tvOS 不依赖系统音乐选择器，使用应用内的电视 Focus 选歌页：展示最近播放、音乐资料库中的播放列表、最近歌曲，并支持检索 Apple Music 目录中的歌曲、专辑和播放列表。选择结果创建 Photo Earth 自己的 `ApplicationMusicPlayer` 队列，不接管 Music App 当前的播放队列。
- 用户选定后才开始流式播放；控制层提供上一首、播放／暂停、下一首和更换配乐。队列不影响 Apple Music 收听历史，不保存歌曲文件，也不把音乐 ID、资料库内容或播放历史写入照片索引、SQLite、KVS 或分析系统。
- 放映播放控件使用底部紧凑的纯图标胶囊；背景音乐单独放在右上角正方形面板，画面只保留灰白音符、歌名和作者，不显示「背景音乐」文字标题，但容器必须继续提供对应的本地化 VoiceOver 分组名称。当前曲目封面按方形裁切铺满整个面板，并叠加顶部约 14%、中部 24%、底部 66% 的渐深半透明黑色遮罩，使封面更清楚且底部信息与按钮仍有稳定对比度；封面缺失或加载失败时使用中性黑灰渐变占位，不额外引入粉紫强调色。操作按钮本体不显示文字，但必须保留完整 VoiceOver 名称。歌名或作者只在实际超出可用宽度时低速往返滚动并在两端停留；Reduce Motion 下使用单行尾部截断。
- 配乐跟随整场放映的暂停、继续、前后台和退出。由于 tvOS 的 MusicKit 播放器没有应用可控音量，用户打开 Live Photo／视频原声且动态媒体实际发声时，配乐暂停，原声结束后再继续；本版不做音量 ducking、交叉淡化或双路混音。
- 照片切换节奏与音乐队列彼此独立，不按歌词、节拍或某个时间点触发指定曲目；不导出、不分享、不录制含 Apple Music 音频的成片。
- Live Photo 和视频原声默认关闭；控制层提供本次放映的「打开原声」。该选择只影响当前放映，首版不写入 KVS。
- 离开当前项、退出放映、应用进入后台或资产发生变化时，立即暂停并取消过期动态媒体请求。
- 动态媒体仍不进入静态 `UIImage` 缓存，也不预取完整视频。地球开场期间先准备首项；播放期间当前项请求优先，该请求完成后只允许准备唯一的下一项。下一项成为当前项时提升同一份 `PHLivePhoto`／`AVPlayerItem`，不得取消后重新请求。
- 纯观看的照片／Live Photo／视频阶段不在画面底部常驻显示日期、地点、媒体类型、位置计数或缓冲文案。底部中央只保留最多 24 段的无文字播放进度轨：精选模式一项对应一段，已播放段、当前段与未播放段用亮度和高度区分；完整模式超过 24 项时按全场比例聚合，VoiceOver 仍读出精确位置。
- 左下角显示无文字、不可聚焦的 MapKit 地球点位缩略模块，使用当前照片真实 GPS 和纯卫星影像；不得用章节中心或城市中心冒充照片位置。它复用照片详情的点位表达但不提供播放中跳转，不能遮挡地图法务署名。跨日期时间印记、地球桥接和用户主动展开控制层时允许暂时隐藏该模块与进度轨。

## 9. 准备、网络和资源预算

- 复用全应用共享图片调度器的本地 4／网络 2 总预算，放映不得另开一套不受控的 PhotoKit 队列。
- 现有相邻预取不允许访问网络；实现时可以增加有界的「放映下一项」优先级，但它仍计入全局最多 2 个网络请求。
- 首章达到 6 个不重复可用项后开始；后续章节在当前播放期间继续准备。
- iCloud 阶段显示实际已分析数和已就绪数，例如「正在准备 6/24」，不能用定时器伪造百分比。
- 当前与即将进入的适屏图片最多同时保留两张；转场完成后释放退场大图。
- 适屏静态帧在地球开场和当前项停留期间做单项前瞻；动态媒体同样只有一个前瞻槽。预取失败不阻塞队列，仍以静态封面继续。
- 视觉分析只使用小缩略图；适屏图继续遵守接近 3840 px 长边、而非请求原始像素文件的策略。
- 一次放映最多分析 96 个候选，不能为了凑满 24 项遍历或下载整个城市图库。
- generation、资产 ID 和当前计划 ID 必须共同阻止迟到缩略图、Vision 结果、适屏图或动态媒体覆盖新状态。
- 内存告警时先取消未播放候选与视觉缓存，保留当前画面；不足以继续时安全退出到来源墙并说明原因。

## 10. 遥控器与控制层

纯观看状态下：

| 输入 | 行为 |
| --- | --- |
| Play/Pause | 暂停或继续整场放映，包括当前计时与动态媒体 |
| 左／右 | 上一个／下一个回忆；手动切换保持快速叠化，微漂移方向与输入一致 |
| 中键 | 显示或隐藏放映控制层 |
| 上 | 打开放映控制层并进入标准 Focus |
| Back/Menu | 退出放映，返回来源照片墙 |

- 控制层至少提供播放／暂停、上一个、下一个、原声开关、重新开始和返回照片墙。
- 播放和音乐按钮使用 SF Symbols 纯图标表达，只在辅助功能中提供文字名称；不在按钮表面重复功能文案。
- 控制层使用标准 tvOS Focus；任何已聚焦控件不能被超时自动移除。
- 只有不可聚焦的提示和控制层背景可以在无操作后淡出。
- 后续内容缓冲在纯观看状态只使用无文字活动指示，不能重新引入底部状态句子；具体状态可由 VoiceOver 宣读或在用户主动展开控制层后呈现。
- VoiceOver 开启时默认显示控制层，并为章节、当前位置、媒体类型和相似照片模式提供可读状态。
- 放映暂停时保持当前照片、标题或地球稳定画面，不回到照片墙，也不释放恢复所需的当前资源。

## 11. 状态机与现有架构衔接

建议由 `@MainActor EarthSlideshowCoordinator` 持有以下显式状态：

```text
idle
  → preparing
  → earthIntro
  → chapterTitle
  → presentingItem
  → transitioningItem
  → earthChapterBridge
  → ending
  → completed
```

`paused` 是对稳定展示状态的正交控制；`failed` 和 `cancelled` 必须能从所有异步状态进入。状态转换由单一协调器拥有，SwiftUI View 只负责呈现，不能让多个 `.task` 各自推进播放索引。

建议新增：

- `EarthSlideshowPlanBuilder`：读取稳定集合快照、分配章节、进行时间取样。
- `PhotoSimilarityAnalyzer` actor：缩略图规范化、Vision Feature Print、美学评分和有界比较。
- `SlideshowTransitionDirector`：从内容关系产生确定性转场。
- `EarthSlideshowCoordinator`：播放时钟、暂停、跳过、媒体与相机状态。
- `EarthSlideshowView`：照片、标题、准备状态和控制层。

现有能力的复用点：

- `TravelPlace` 已表达一次按空间和时间分开的到访。
- `PlaceCollection` 已表达单次到访和同城市多次到访成员。
- `SQLiteTravelIndexStore` 已提供稳定照片分页与读取快照。
- `SharedPhotoImageScheduler` 已提供跨页面去重、取消、本地／网络预算和尺寸缓存。
- `PhotoDetailPlayback` 已提供 Live Photo 与普通视频的 PhotoKit／AVFoundation 请求生命周期。
- `GlobeExperienceModel` 与常驻 `MKMapView` 已提供受应用控制的地球相机和 Reduce Motion 分支。

两种照片墙都必须接入同一个放映协调器。集合墙当前作为透明 `fullScreenCover` 存在；实现时应把放映会话提升到能够同时控制常驻地球与来源墙恢复锚点的宿主，不在集合墙内部创建另一张 MapKit 地图。

## 12. 错误与降级体验

| 情况 | 用户体验 |
| --- | --- |
| 地球影像尚未清晰 | 按当前 MapKit 结果继续并显示星空／真实地球，不宣称高清已完成 |
| 首章部分照片仅在 iCloud | 地球开场期间继续准备；超时后显示真实准备状态和取消操作 |
| 某张适屏图失败 | 保留可用预览；仍失败则跳过，不让旧图冒充新图 |
| Live Photo／视频失败 | 使用静态封面继续，并提供稍后重试能力 |
| Vision 不可用或失败 | 使用保守时间／位置降级，不删除候选 |
| 图库资产被删除或权限撤销 | 取消请求；权限撤销时立即退出并隐藏私人内容 |
| 章节只剩一项 | 正常播放，不复制照片来延长时长 |
| MapKit 跨城市残影复现 | 记录为既有原生渲染限制，不把转场完成当作问题已修复 |

## 13. 验收标准

### 产品与算法

- 标注样本中，明显复制／连拍相似图的合并召回目标至少 80%。
- 有意义的不同照片误合并率目标低于 1%；精确率优先于召回率。
- 不同到访中的同地标照片除近乎完全相同的复制品外不得合并。
- 收藏照片不会被未收藏的自动美学高分照片替代。
- 相同输入和算法版本生成完全相同的章节、顺序、代表项和转场。
- 「完整放映」不应用视觉相似去重，并能跨现有分页边界继续读取。

### 性能与网络

- 候选、特征比较、适屏图和动态媒体均有硬上限；不存在全图库图片扫描或无界任务。
- 本地内容的首章目标在用户开始后 3 秒内可播放；iCloud 情况不承诺固定完成时间，但必须立即显示真实阶段并可取消。
- 放映期间最多两个适屏静态帧同时参与转场，图片与媒体请求服从现有全局预算。
- 退出、后台、删除、权限变化和快速连按后没有迟到内容回写。
- 在所有支持 tvOS 26 的 Apple TV 4K 上以 Release 构建测试；模拟器和开发 Mac 的 Vision 探针不能代替真机帧时间与热状态。

### 转场与交互

- 自动前进、手动前进和手动返回的方向一致，无反向滑动。
- 连续回忆可以重复纯叠化；导演不会为展示效果数量机械插入推页，地球只出现在规定章节边界。
- 任意阶段 Play/Pause、左右和 Back 都能打断或安全收束当前动画，不等待长动画结束。
- Reduce Motion 下没有自动地球飞行、推移、缩放、视差或动态模糊，地点与日期语义仍完整。
- Focus 不会因自动淡出丢失；VoiceOver 能完成开始、暂停、跳过、打开原声和退出。
- MapKit 法务署名在所有地球画面中保持可见。

### 必需测试

- 纯 Swift：章节配额、时间分桶、确定性排序、候选硬上限和转场选择。
- Vision fixture：复制、裁切、调色、连拍、同景不同日、跨年重访和跨媒体封面。
- 调度器：本地／网络预算、优先级、取消、超时、内存告警与迟到结果。
- 状态机：每个状态的暂停、继续、左右跳转、失败、后台与退出。
- UI：单次到访、同城多次到访、首章不足 6 项、48 项分页边界、完整放映、Reduce Motion 和 VoiceOver。
- 真机：最早支持目标 Apple TV 4K、真实 iCloud 本地／云端混合、Live Photo、长短视频、声音、HDR、持续多章播放和跨城市 MapKit 转场。
