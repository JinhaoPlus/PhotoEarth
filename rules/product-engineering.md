# 产品、工程与数据

## 产品目标与体验原则

PHOTO EARTH 是一款原生 Apple TV 旅行照片应用。

用户授权访问 iCloud Photos 后，应用自动读取带地理位置的照片，通过拍摄时间和 GPS 生成旅行地点、城市与旅程，在一颗具有电影感的可交互地球上呈现地点和照片。主地球不绘制地点之间的旅行连线；旅程推断与索引数据继续保留。

### 最高设计要义：震撼人心的美感与深层情绪价值

PHOTO EARTH 首先是一件承载个人记忆的视听作品，其次才是一款地图或照片工具。它必须让用户在电视前看到自己走过的世界被重新点亮时，产生惊叹、感动、怀念和“这是只属于我的地球”的情绪连接。

这不是可有可无的视觉润色，而是产品存在的核心理由，也是所有设计与实现决策的最高优先级：

- 每个主要页面都应追求电影开场般的构图、尺度、光影、节奏和声音想象，而不是信息面板的堆叠。
- 地球、照片和旅程记忆永远是视觉主角；控件应克制、安静，并在不需要时退入背景。
- 动效的目标是唤起情绪：从宇宙看向一座城市、从地点进入一张旧照片，都应像记忆被逐渐唤醒，而不是普通的页面跳转。
- 大屏体验要敢于使用留白、黑场、超大尺度、缓慢镜头与高质量照片，让用户有时间感受，而不只是快速完成操作。
- 真实照片比装饰元素更重要；任何特效都必须服务于记忆与地点，不得沦为与内容无关的炫技。
- 功能完整但情绪平淡的方案不算完成。实现后必须在真实 Apple TV 尺寸上审视：第一眼是否震撼，停留观看是否有情绪余韵，进入照片时是否感到这是自己的人生轨迹。
- 当易实现、信息密度或传统工具惯例与情绪体验冲突时，在不损害可用性、隐私和稳定性的前提下，优先保护情绪体验。

核心承诺：

- 不要求用户导入文件、填写坐标或预先整理旅行数据。
- iCloud Photos / PhotoKit 是照片与原始元数据的唯一事实来源。
- 首次授权和扫描结束后，用户可以直接进入旅行地球。
- 默认在设备端完成照片筛选、地点聚类和旅行推断。
- Apple TV 主要承担浏览和播放，不承担繁重的数据编辑。
- 视觉与情绪体验优先于传统地图工具体验，要像一部由用户人生构成的“私人旅行电影”，而不是地图后台或照片管理器。

灵感来源是开源项目 [Aisland-SJL/StarMap](https://github.com/Aisland-SJL/StarMap)。可以借鉴其旅行数据结构、镜头语言、照片分层和视觉表现，但不得尝试直接移植 React、Cesium、DOM 或 CSS 实现。

## 七天试用与买断

- 所有用户共用原首页、五项侧边栏、地球、照片墙与放映开场。浏览、移动焦点、选城市、选年份列表、配置放映范围与配乐都不启动试用。在原按钮真正打开照片墙或开始放映时核对权益；「稍后再说」、遥控器返回和取消系统确认都留在原位置，成功后接着执行原操作。
- 首次打开一段旅程的照片墙，或在原放映选择器选中单段并开始播放，就在本机记住这段免费旅程。跨入口按旅程成员判断；到访、城市、国家按原集合，地图画面按冻结的投影，往年当天按当日照片。空范围直接显示原空态。按放映快照中的实际旅程判断。图库只有一段旅程时，「全部旅程」也可免费播放。另一段旅程或跨旅程范围才提示试用或买断。
- 零元非消耗型试用从 StoreKit 原始购买时间起算，满 168 小时回到免费权益，保留索引和原有导航。试用期内不占用免费旅程名额；到期时尚未选过的用户可在后续第一次打开单段旅程时选定。试用到期中断放映时，返回原入口并短暂显示非模态说明，焦点留在原页面。到期不自动扣费，恢复购买不重置时长。个人 Top Shelf 仅在完整权益有效时发布。
- 完整版为一次性非消耗型内购，购买后永久解锁全部旅程。应用文案说明一次性购买、试用期限和到期影响。具体金额由 App Store 按地区配置，在系统购买确认框展示。退款撤销后重新核对现有权益。设置在未试用、试用中和到期后均提供完整版购买入口，已买断显示购买状态。每次购买都由用户确认。设置在右栏内展示购买选项，旅程与放映继续使用原地弹窗。试用与一次性购买放在主操作区，恢复购买单列。试用中展示实际到期时间、到期后权益及买断入口。
- 模拟器专项使用 Xcode StoreKit 的购买确认框和测试交易，时间推进仅编译到 Debug 模拟器。发布门禁覆盖试用、到期、买断、重启及退款。
- 真机 Debug 包默认跳过购买，从电视主屏幕启动也能测试个人图库。模拟器日常 Run 通过 `PHOTOEARTH_UI_OWNED_FIXTURE=1` 跳过购买。手动测内购时，在 Run → Arguments 将该变量设为 `0`。Test 独立配置启动环境，Debug 和 Release 的 Top Shelf 购买权限分开保存。

## 平台与职责

- 使用原生 Swift／SwiftUI 与 tvOS Focus System，目标设备为支持项目最低系统版本的 Apple TV 4K。实际 deployment target 以 `PhotoEarth.xcodeproj/project.pbxproj` 为准。
- MapKit 承担地图、地球、相机与原生标注。RealityKit 仅在 MapKit 无法提供所需效果时用于独立氛围层或转场。沿用原生地图与媒体框架，避免另建球面渲染器、瓦片系统、引入第三方 3D 地图或照片库依赖。新代码使用 RealityKit 处理需要的非地图特效。
- `App/` 管理应用状态和协调器，`Features/` 管理界面与交互，`Domain/` 放置可独立验证的值类型和算法，`Services/` 封装 PhotoKit、离线目录与持久化，`Rendering/` 管理 MapKit 画面和标注。Top Shelf 扩展及共享结构位于 `PhotoEarthTopShelf/` 与 `PhotoEarthTopShelfShared/`。
- 照片与原始元数据来自 iCloud Photos／PhotoKit。地理归组和距离计算在设备端执行。Vision 只分析有限小图，用于放映候选和封面。SwiftUI View 通过服务边界使用 PhotoKit、索引和偏好。

## SQLite 派生索引

iCloud Photos / PhotoKit 是照片、拍摄日期与 GPS 的唯一事实来源。应用生成的索引是可丢弃、可重建的派生数据。

### 本地派生索引

完整索引保存在本地可清理缓存中。项目从一开始就按 5 万张带位置照片设计，正式实现统一使用原生 SQLite；不得把全部照片记录编码为单个 JSON，也不得在启动时把全部照片记录一次性解码进内存。索引至少包含：

- schema 版本和生成时间。
- 照片本地标识与必要的轻量元数据。
- 地点聚类、城市和国家。

- 每张带地点照片的本地标识、坐标、日期、尺寸、收藏状态和所属地点 ID；这些字段用于当前地表视野查询。

要求：

- 启动阶段只读取 schema、生成时间、扫描统计、地点摘要和旅程摘要；单张照片记录留在数据库中按需查询。
- 地点摘要只保存 `photoCount` 和 `coverAssetID`，不重复保存完整照片 ID 数组。
- 照片表按所属地点与拍摄时间建立普通索引，并使用 RTree 保存经纬度空间索引。
- 世界尺度的视野查询先按空间范围和固定地理网格选取少量代表候选，再在内存中做球面距离、背面剔除与多样性排序；不得把半个地球的所有照片读入内存。
- 按地点浏览照片时使用稳定排序与分页查询，不预载该地点的全部资产 ID。
- 全量重建使用单个 SQLite 事务和复用的预编译语句，避免逐记录提交；启用 WAL，并将数据库视为可丢弃缓存。
- schema 不兼容、数据库损坏或迁移失败时丢弃 SQLite 主文件及其 WAL/SHM 辅助文件，再从 PhotoKit 重建。
- 不将缩略图嵌入索引。
- 不假设缓存一定长期存在。

索引还保存地点与旅程分组、离线城市匹配、策略和目录版本、封面引用。优先原地迁移可用数据，启动只读摘要和统计。

## 轻量偏好与隐私

`NSUbiquitousKeyValueStore` 只保存少量用户偏好和同步状态，不保存完整照片索引。

- Debug 配置不携带 iCloud KVS entitlement，使用 `UserDefaults` 本地持久化，以便 Personal Team 可以签名并在 Apple TV 真机调试。
- Release 配置保留 iCloud KVS entitlement 和 `NSUbiquitousKeyValueStore`；正式签名需使用支持 iCloud 能力的付费 Apple Developer Team。
- Debug 关闭 KVS 不影响 PhotoKit 读取用户照片库中已由 iCloud Photos 同步的照片、时间和 GPS 元数据。

可以保存：

- onboarding 是否完成。
- autoplay 等显示偏好。
- 上次选择的年份或旅行。
- 隐藏/收藏旅行的稳定 UUID。
- 用户指定的封面映射，前提是总体积保持很小。
- 偏好 schema 版本。

禁止保存：

- 每张照片的 ID、坐标和日期列表。
- 完整地点或旅行索引。
- 原始或推断的家庭位置。
- 缩略图和照片二进制。
- 任何密钥或 token。

KVS 硬限制是总值 1 MB、最多 1024 个 key、单值最大 1 MB；项目应把实际使用量控制在远低于上限的几十 KB。同步是异步的，启动时必须允许暂时使用本地默认值，并监听外部变化通知。不要把 `synchronize()` 当成立即上传或事务提交。

如果未来需要在多个设备间同步大量人工编辑结果，使用 CloudKit Private Database；不要通过扩大 KVS 单个 JSON blob 来绕过设计边界。

- 请求照片权限前必须说明用途，不在启动瞬间无上下文弹权限框。
- 默认只请求读取所需的最低权限，不修改或删除用户照片。
- 地点、旅行和常驻地推断默认只在设备上处理。
- 日志不得输出完整照片标识、精确坐标或文件内容。
- Debug 示例和截图只能使用中性模拟数据，除非用户明确授权使用其私人照片。
- KVS 不保存精确位置或其他敏感信息。
- 删除应用缓存不得影响 Photos/iCloud 中的任何资产。

## 编码与并发

- 使用现代 Swift Concurrency，UI 状态更新保持在 MainActor。

- 支持任务取消；离开 onboarding 或重新扫描时结束旧任务。
- 模型优先采用值类型、`Codable`、`Sendable`。
- 避免在 SwiftUI View 内直接堆积 PhotoKit、聚类与缓存逻辑。
- 所有错误都应转换为用户可理解且可恢复的状态。

- 长时间照片扫描、聚类、序列化和离线地名匹配在主线程之外执行。

- 将权限拒绝、iCloud 离线、图片下载失败和索引损坏转换为明确的用户状态。诊断只记录必要计数、聚合时延或错误域／码，省略照片 ID、地名、精确坐标、媒体内容与可能包含私有数据的错误详情。

## PostHog 使用统计

主 App 通过 `Analytics.xcconfig` 读取公开 Project Token 和对应区域的 ingestion host。Debug、模拟器和预览停用线上采集，未配置时不初始化 SDK。配置有效时默认开启，可在设置中关闭。偏好只保存在本机，关闭即停止采集并清除该项目的本地队列和安装标识。

事件使用 `photoearth_` 前缀和 `product=photoearth`。按看板问题记录进入前台、首次连接图库、体验示例、功能入口、照片墙访问结果、放映生命周期和设置变更。SDK 发送前按白名单重建属性，统一带入版本、构建号、渠道、平台、系统版本、系统首选语言、界面语言和埋点版本。主 App 只记成功接住的 Top Shelf 入口类别。扩展曝光、照片、相册、地名、坐标、曲目和错误原文均不采集。发布前按实际采集核对隐私政策及 App Store Connect 的设备标识与产品交互披露。具体口径见[用户动线与看板](../Docs/FeatureMap/analytics.md)。

埋点以进入功能或关键操作为单位。一次照片墙访问退出时仅汇总是否看过详情。单张照片曝光、打开详情、翻片、焦点移动和放映换片均不触发事件。一场放映的内部重试复用同一请求，至多记录一次开场、一次进入配乐选择和一次结束。跨越关闭统计的访问不补报。

启动、Focus 导航和放映的埋点调用只投递事件。PostHog 初始化、事件编码与落盘、关闭及缓存清理在独立的串行后台队列执行。积压达到上限时丢弃新事件，关闭使用统计时作废尚未处理的事件。
