# 照片库授权、扫描与筛选

## 授权与扫描资格

- 在用户主动选择生成旅行地球后请求照片库权限。提前说明会读取拍摄时间、GPS、相机证据与所选相册成员。首次选范围时，按 Back 放弃本次草稿，回欢迎页或发起连接的示例设置。再次进入由用户主动连接。允许保留默认范围，点「开始扫描」后才开始。已有图库的范围编辑同样由「保存范围」提交，Back 放弃草稿。首扫与编辑的提交按钮均在范围标题右侧，进入页面时优先聚焦。
- 全量、增量和缓存恢复使用同一资格规则。默认排除截图、录屏、无有效时间或 GPS、确认无相机信息的媒体。相机证据未知时先保留并单独计数。静态照片、Live Photo 与普通视频各按一个资产计数。
- 排除相册以 PhotoKit 本地相册 ID 保存，多个相册取成员并集。资产一旦确认受排除或权限收窄影响，首页、地图、墙、详情和播放及预取立即移除。图库只读。
- 限制相机证据读取并发，区分已确认缺字段和暂不可读。首轮扫描不批量下载原件。资格、相册成员、统计与索引发布的规则见 [旅途扫描改造](../Docs/JOURNEY_SCAN_AND_LONG_SLIDESHOW_PLAN_2026-11-19.md) 第 2 至 3 节。

## 元数据与 PhotoKit 变化

扫描阶段只读取生成索引所需的信息：

- `PHAsset.localIdentifier`
- `location`
- `creationDate`
- `mediaType` / `mediaSubtypes`
- `pixelWidth` / `pixelHeight`
- `isFavorite`
- 视频 `duration`

首版索引静态照片、Live Photo 与普通视频：Live Photo 由 `mediaType == .image` 且 `mediaSubtypes` 包含 `.photoLive` 判定，普通视频由 `mediaType == .video` 判定并保存时长。三者共用 GPS／时间聚类、空间查询、地点归属、封面与分页规则；360° 全景、空间／沉浸式视频和 RAW 特殊展示仍推迟到后续版本。

不要把照片原始二进制复制到应用自己的永久数据层。需要显示图片时通过 `PHImageManager` / `PHCachingImageManager` 请求合适尺寸，并允许 PhotoKit 按需从 iCloud 下载。

- 运行期间使用 `PHPhotoLibraryChangeObserver` 响应新增、删除和元数据变化。
- 跨启动的增量标记只是一种性能优化，不能成为唯一正确性来源。
- 定期或在缓存异常时执行完整的轻量元数据复核，避免漏掉旧照片的位置或时间编辑。

- 启动先展示有效缓存，并在后台复核。使用持久变化令牌时，从复核前的令牌回放变更，失败或取消后保留有效基线。相册成员在启动与回前台主动对账，暂不可读时保留上次有效排除范围。
- 恢复既有索引时，同时核对随包地名库与到访分组规则版本。权限、相册范围、相机资格一致，且变化令牌和近期完整复核仍有效时，复用索引中的原始坐标及日期，回放图库变更后再重新分组。目录、分组规则和语言均一致时，原资产及其坐标未变可复用已发布的城市身份。语言变化只按既有到访更新名称。
- 增量回放在收到首批资产变化时建立暂存。若资产、权限、目录与相机证据均未变化，且来源总数与已发布摘要一致，只原子更新安全令牌和复核时间。令牌过期、到期的每周复核、受限权限及未完成的暂存仍可触发完整复核。
- 暂存结果在 SQLite 原子发布。缓存缺失或不可用时从 PhotoKit 重建。准备界面显示实际核对阶段、照片与地点计数，增量发布按当前资格过滤。首个有效索引就绪后交接到同一张地球，空库直接展示可恢复状态。
- 准备进度与设置流程的设计见 [照片库准备](../Docs/PHOTO_LIBRARY_PREPARATION_PLAN_2026-09-10.md)，地名部分沿用现行离线流程。
- 在准备页按 Back 回来源，整理在应用内继续。首次整理尚未建成索引时，从欢迎区可以再打开进度。「暂停扫描」中断整理，「继续」从已保存的位置恢复。

## 疑似途经照片

- 正式照片库默认开启本机「隐藏疑似途经照片」，可在设置关闭并立即恢复，无需重扫，不修改 PhotoKit 或删除原始索引。示例展示保持原样。
- 按一次原始访问判断零散记录：1–2 个资产、拍摄跨度不超过 30 分钟、整次访问无收藏时隐藏。拍摄跨度不是实际停留时长；这是允许误判但可恢复的产品启发式规则，不宣称识别交通方式。
- 独立高速规则使用按拍摄时间和 ID 稳定排序的相邻照片：连续两段平均位移速度均为 400–1400 km/h、每段间隔 1 分钟至 6 小时，才隐藏中间非收藏照片；不因单段远距离移动直接隐藏两端。排除已知水平精度差于 1000 m、无效时间以及明显折返的 GPS 跳点。阈值集中于 `TransitFilteringConfiguration`，不是航空或交通识别的准确率承诺。
- 海拔只辅助标记：有效垂直精度不超过 100 m，扣除误差后海拔仍达到 8000 m，并满足上述高速规则时记录更强原因；绝不只凭海拔隐藏高原、登山照片。海拔和精度缺失时保持为空，不伪造 0 或要求下载原图。
- 收藏照片不受高速规则隐藏；零散访问若含收藏，整次访问保留。普通静态、Live Photo、视频按一个资产计数。

- 途经过滤作用于合格图库的可见读取策略。保留原始聚类成员与城市身份，派生可见摘要同步更新访问起止时间、张数、封面和旅程成员。设置分别展示可见和隐藏数量。

- 分类流式读取，Swift 只保留三张相邻记录；不全库解码照片、不请求额外网络服务。原始元数据、收藏或算法版本改变时重算；切换开关只改读取策略。已有照片墙固定原 WAL 快照及过滤策略，不能在分页中途改变成员。
- 全部照片被过滤时仍保留可进入设置的地球界面，明确提示可恢复。过滤结果有独立内容版本，不能只用扫描时间决定光点和首页货架是否刷新。
- 本轮实现与验证记录见 `Docs/TRANSIT_FILTERING_2026-10-03.md`。启发式误判率、真实 PhotoKit 海拔字段覆盖率和实体遥控器手感需真机验证。
